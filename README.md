# ASSEMBLY OS — веб-платформа

Интегрированная цифровая система управления Ассамблеи экономики Узбекистана.
Реализация веб-части ТЗ: вход по логину/паролю, роли, личные кабинеты,
конвейер поручений, чат и статистика объединений.

## Запуск

```bash
npm install
npm run seed     # создаёт data/assambleya.db с демо-данными
npm run dev      # http://localhost:3000
```

Пароль всех демо-аккаунтов: **12345678** (список аккаунтов раскрывается прямо на
экране входа).

| Логин | Роль |
|---|---|
| `rais` | Rais — председатель, командный центр |
| `gr.rahbar`, `fr.rahbar`, `br.rahbar`, `pr.rahbar` | Руководители 4 отделов (GR/FR/BR/PR) |
| `ailab.rahbar` | AI Lab — цифровой штаб |
| `gr.xodim1` … `ailab.xodim3` | Сотрудники отделов (подчинённые) |
| `tekstil.rais`, `agro.rais`, … (12 шт.) | Председатели объединений |
| `casc.rahbar`, `kng.rahbar`, … (10 шт.) | Руководители проектов из ТЗ |

Прочие команды: `npm run build`, `npm start`, `npm run reset-db` (пересоздать БД).

## Что реализовано

**Вход.** Платформа сразу требует логин и пароль: `/` редиректит на `/login`,
все страницы и API закрыты серверной проверкой сессии. Пароли — scrypt,
сессия — подписанный HS256-токен в httpOnly-cookie (12 ч), смена пароля в профиле.

**Роли.** `RAIS`, `UYUSHMA_RAISI`, `LOYIHA_RAHBARI`, `BOLIM_RAHBARI` (4 отдела),
`AI_LAB` и их подчинённые (`ISHCHI`). Меню, страницы и права в API зависят от роли;
сотрудник не может выдавать поручения, утверждать результат может только автор.

**Личный кабинет** у каждого: счётчики поручений, просрочки, последние задачи,
быстрые действия; у Раиса дополнительно командный центр (итоги по организации,
разрез 4 отделов + AI Lab, топ объединений).

**Конвейер поручений** — 4 страницы для руководителей отделов и AI Lab
(у сотрудников только первые две; у Раиса — только 3-я и 4-я, поручения ему
никто не выдаёт):

1. `/tasks/inbox` — приём поручений (принять / отклонить);
2. `/tasks/execute` — исполнение (начать работу, сдать результат);
3. `/tasks/assign` — выдача поручений отделам и сотрудникам + все отправленные с фильтром по статусам;
4. `/tasks/review` — приём результатов от сотрудников (утвердить / вернуть на доработку).

Статусы: `YANGI → QABUL_QILINDI → BAJARILMOQDA → TEKSHIRUVDA → BAJARILDI`,
плюс `QAYTARILDI` и `RAD_ETILDI`. Каждый переход пишется в журнал `task_events`.

**Чат.** У всех есть прямой чат с Раисом (закреплён сверху) и переписка с любым
сотрудником: в левой панели две вкладки — «Суҳбатлар» (диалоги) и «Ходимлар»
(весь штат, сгруппированный по отделам, объединениям и проектам, с фильтром по
имени/отделу). Непрочитанные показываются бейджем, тред обновляется опросом раз
в 5 секунд.

**Статистика объединений** — `/statistics`: сводные KPI, распределение поручений
по статусам, сортируемая таблица 12 объединений (члены, проекты, поручения,
уровень исполнения, просрочки) и карточки 10 приоритетных проектов из ТЗ.

**Языки.** O'zbekcha (лотин), Ўзбекча (кирилл), Русский, English — переключатель в
шапке и на экране входа, выбор сохраняется в cookie и в профиле пользователя.
Тёмная и светлая тема.

## Стек

Next.js 16 (App Router) · React 19 · TypeScript · Tailwind CSS v4 ·
SQLite через встроенный модуль Node `node:sqlite` — внешних зависимостей и
сервисов не требуется.

## Структура

```
db/schema.sql              схема БД
scripts/seed.mjs           демо-данные (детерминированные)
src/lib/                   db, auth, session, queries, i18n, format
src/components/            app-shell, task-list, ui-кит, иконки
src/app/login/             экран входа
src/app/(app)/             защищённая зона: dashboard, tasks/*, chat/*, statistics, team, profile
src/app/api/               auth, tasks, chat, locale, profile
```
